# 拾语视觉基线

这份基线是新增页面和组件的验收契约。它记录当前产品的视觉方向、状态表现和固定视口，评审截图差异时优先比较布局、层级和状态，不追求逐像素冻结动态文案。

## 视觉方向

拾语是一个安静的桌面工具，不是一个营销页面。界面以中性灰画布和纯白内容面板构成，主操作是石墨色实心按钮，强调色（靛蓝）只出现在焦点环、链接与选中指示上。不要引入暖米白、大面积品牌色填充、渐变、装饰性发光或大号营销标题。

记录页是整屏双栏工作台：左栏「识别结果」放语音识别原文，右栏「转写内容」放整理后的文字；两栏共用同一张内容面板，中间只隔一条 1px 竖线，不叠卡片，也没有欢迎区。工作区本身是一张带 1px 边框、14px 圆角与卡片落影的面板，四周留 16px 外边距（≤680px 收到 10px），内容不贴侧栏、顶带与窗口边缘。两栏栏头、栏脚与正文起始线左右对齐（栏头按较高的录音按钮定高），中间是一条可拖动的分隔线。栏头的模型与语言都是下拉框，直接切换当前配置。

浅色与深色共用一套规则：颜色全部来自 Radix Themes 的色阶，`<Theme appearance>` 切换时自动翻转。主窗口的画布由 AppShell 绘制，内容面板、列表卡片和弹窗保持不透明；浮动模式没有画布，整页透明。

颜色、间距、圆角与布局变量集中在 [`frontend/src/styles/theme.css`](../frontend/src/styles/theme.css)，全局 reset 与平台窗口层变量在 [`frontend/src/styles/global.css`](../frontend/src/styles/global.css)。组件样式一律是就近的 `.module.css`。

## 品牌标记与图标

品牌标记是「声纹成字」：左边三根竖条是声纹，右边两条横线是整理后的文字，最高的一根竖条与两条横线共用上下基线。从左往右读就是产品的动作——说话，然后变成文字。

权威几何只有一份：[build/icons/app-icon.svg](../build/icons/app-icon.svg)。应用图标、favicon 与 DMG 文件图标（反相配色）都由它与同目录的变体 SVG 渲染：`common:generate:brand` 出位图，`common:generate:icons` 再把位图转成 `.icns` / `.ico`。**改图标只改 SVG，不要直接改 PNG、ICO、ICNS。**

| 用途 | 源 | 规则 |
| --- | --- | --- |
| 应用图标（macOS / Windows / Linux） | `build/icons/app-icon.svg` | 石墨砖 `#202020`（Radix gray-12 浅色档）+ 白色声纹 + 靛蓝文字线；砖外边距 100、圆角 184，内容 824² |
| DMG 文件图标 | `build/icons/dmg-file.svg` | 反相配色：白砖 + 石墨标记，与应用图标一眼分开（文件不等于应用） |
| DMG 窗口背景 | `build/icons/dmg-background.svg` | 中性灰渐变，不出现任何第三方标识 |
| favicon | 由 `app-icon.svg` 渲染成 64² | 自带砖底，标签页在明暗两套系统外观下都可见 |
| 托盘图标 | `build/icons/tray.svg` | 单色声纹几何（去砖底），静态、录音不换图（macOS 系统自带麦克风使用中指示）。Windows 中灰 `#8E8E93`（`idle.png`）；macOS 黑稿 `template.png` 以系统模板图加载，深浅菜单栏与失焦/高亮自动适配，与邻近图标一致；`generate:brand` 渲染 44×44 PNG 到 `desktop/assets/tray/`，由 Go embed 嵌入 |
| 应用内标记 | [frontend/src/components/BrandMark.tsx](../frontend/src/components/BrandMark.tsx) | 小尺寸精简版：两柱两线、`currentColor` 单色，随主题翻转 |

小尺寸规则：应用内标记用 24 网格，柱宽 = 线高 = 3.4，竖组间距 2.6，14–18px 下仍能读成「左竖右横」。五元素全量版在 32px 以上各自清楚，16px 帧（Windows ico）只保留砖的剪影与声纹节奏；这是刻意取舍，不另做第二套小尺寸艺术稿，两套稿才是不一致的根源。

对比度按 WCAG 对石墨砖 `#202020` 实算：白色 16.3:1、靛蓝 `#5472E4` 3.8:1，都高于非文本图形 3:1 的下限。应用内标记不写死颜色，浅色主题继承 `--app-ink`，深色主题自动变近白。

## 固定视口

| 视图 | 视口 | 期望结果 |
| --- | --- | --- |
| 桌面主视图 | 1280 × 820 | 236px 侧栏、36px 顶带（窗口按钮与品牌同一行）；双栏工作区卡片四周留 16px 外边距：左栏「识别结果」带栏头录音控件与模型/语言下拉框，右栏「转写内容」，两栏栏头与栏脚各自对齐，没有欢迎区 |
| 窄桌面 | 1024 × 768 | 仍是两栏；栏头里的模型下拉框、语言下拉框与录音控件挤不掉标题，两栏底栏按钮都不折行 |
| 移动端 | 390 × 844 | 侧栏隐藏、顶栏出现菜单按钮；两栏改成上下堆叠（竖线换成横线），栏头控件在栏内换行，设置表单单列 |
| 主窗口最小 | 640 × 640 | 侧栏收成抽屉、两栏上下堆叠各占一半高度、栏头控件折行、底栏不溢出，没有横向滚动 |
| 最小宽度 | 320 × 任意高度 | 标题、按钮和输入框不被裁切，不出现横向滚动 |

主窗口默认 **1000 × 820**（最小 640 × 640）：默认尺寸下工作区卡片铺满内容区只留 16px 外边距，减掉 236px 侧栏后每栏约 374px；窗口窄到 900px 以下两栏改成上下堆叠，再窄到 680px 就切成侧栏抽屉、外边距收到 10px。截图仍按 1280 × 820 的评审视口生成，用来观察宽窗口下两栏的宽度上限（每栏约 514px）。

响应式规则以 `900px`（窄桌面）和 `680px`（移动端）为边界。Chromium 截图只覆盖内容层；原生交通灯、顶带右端的窗口按钮和浮动窗口需要在桌面真机上验收。

## 组件状态

## 桌面专属状态

桌面窗口有两个视觉模式：主窗口是完整工作区（记录页双栏、列表页单列），左侧导航固定、内容区独立滚动，顶部使用原生交通灯（macOS）或顶带右端的 HTML 窗口按钮（Windows/Linux）；浮动模式是 92×126 的透明窗口：顶部 92×92 只显示圆形录音按钮，底部 34px 在悬停时显示操作按钮：待录音时是展开和设置，录音中只剩取消，不出现方形底色、标题栏或交通灯。macOS 的悬停由原生 tracking area 驱动，应用失焦时工具栏也能出现。浮动按钮待录音时是石墨色麦克风，正在开启麦克风时保持麦克风图标并加呼吸环（球体不缩放），录音中才是红色方块并随输入音量放大、带一圈音晕，整理中为旋转图标；缩放后的球加外圈仍在顶部 92×92 球区内，不压到工具栏。交互手势与状态机见 [`docs/desktop-interaction.md`](desktop-interaction.md)。自动粘贴失败时，结果仍保留在剪贴板，不能阻塞历史记录和复制操作。

托盘图标常驻菜单栏（macOS）/ 右下角（Windows）：idle 为中灰 `#8E8E93` 单色声纹，macOS 录音态切换为红色 `#FF3B30` 变体，Windows 图标不变、tooltip 提示录音。隐藏悬浮球后按全局快捷键进入第三形态「底部胶囊」：原生窗口 360×72 透明无边框，停在工作区底部居中（下边距 48px），内部胶囊 320×56、两端全圆角，石墨底（`--gray-12`）+ 白色描边 + 与浮动球同一组阴影（`0 6px 16px rgba(15,15,17,0.28)`）；左侧波形复用记录页录音控件的 17 根竖条（静默保留 14% 细线），右侧 28px 取消按钮。开启麦克风时波形条呼吸，录音中按 `--mic-level` 起伏，录音红与浮动球一致（`--red-9`）。结束后胶囊在 260ms 内用 CSS 收缩成 56×56 的圆（`cubic-bezier(0.32,0.72,0,1)`），波形 120ms 淡出、旋转图标淡入；完成/取消后圆内闪示 Check/X 约 320ms 再隐藏窗口。`prefers-reduced-motion` 下跳过宽度变形与呼吸，直接切换形态，功能不变。胶囊全程不抢焦点，不出现 Toast（窗口马上消失），反馈只靠圆内闪示。

## 人工验收清单

1. 桌面视图没有横向滚动；侧栏与内容区、左栏与右栏之间各只有一条 1px 分隔线，两栏的栏头、栏脚与正文起始线在同一水平线上；拖动中间的分隔线能改变两栏宽度，双击恢复居中。
2. 主窗口栏头只有一枚录音按钮：待录音是石墨麦克风、开启麦克风时加呼吸环、录音中整枚变红为暂停图标、处理中变旋转图标且禁用；主窗口不再出现波形、耗时或状态文字，这些都能在浮窗里看到，两处状态一致。
3. 两栏标题「识别结果」「转写内容」、栏头控件与正文的层级清楚；空态也画出栏头与栏脚，两栏底部不错层，空操作（整理文字、复制）以禁用态出现，不藏在悬停里。两栏底栏按钮同一档尺寸与圆角：次要操作（复制）是浅底软按钮，主操作（整理文字、重新整理）是深色高对比按钮；左栏显示识别原文的字数，右栏显示整理后正文的字数，两个数字分别与各自栏脚左侧对齐。左右两栏都没有「清空」与「编辑」按钮：清空换稿走「新建记录」，右栏在 LLM 输出完成后自动恢复可编辑、直接改字或一键复制；转写或整理进行中两栏只读、复制按钮禁用，结束后自动恢复。
4. Tab 键能依次到达导航、左栏栏头的模型与语言下拉框、录音按钮，再到两栏正文与栏脚操作；两栏同时挂在页面里，不必先切换视图才能到达某个操作；栏头没有设置齿轮，录音设置只在偏好设置弹窗里。

## 生成截图

不引入额外浏览器依赖；已安装 Chromium 或 Google Chrome 的环境可直接运行：

```bash
cd frontend
./scripts/capture-visual-baseline.sh
```

脚本先执行 Vite 构建，再把 `docs/visual-baseline/` 作为唯一输出目录，生成 `idle-1280.png` 和 `idle-390.png`。可通过 `CHROMIUM_BIN=/path/to/chromium` 指定浏览器，或把输出目录作为第一个参数传入。脚本会为 headless 浏览器使用临时用户目录；Edge 等 Chromium 分支会把小窗口钳制到约 492px，生成 390px 截图时请使用 Chromium/Chrome。

没有 Chromium 时，可以用 ego-browser 以 1280×820 与 390×844 两个视口直接截图，深浅两套分别是 `idle-1280.png`、`idle-390.png` 与 `idle-1280-dark.png`、`idle-390-dark.png`。截空态前先清掉 localStorage 里的 `typeless-notes`、`typeless-settings`、`typeless-desktop-settings`、`typeless-sidebar`，只把 `typeless-appearance` 设成 `light` 或 `dark`，再 reload：否则会带上上次的草稿、侧栏收起状态或历史记录。浏览器预览还可以用 `?platform=windows` 强制渲染 Windows 标题栏，方便在 macOS 上检查 caption 布局。截图用于人工差异评审，不追求逐像素冻结；原生窗口层需要在桌面真机上另做验收。

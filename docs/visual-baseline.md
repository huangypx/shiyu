# 拾语视觉基线

这份基线是新增页面和组件的验收契约。它记录当前产品的视觉方向、状态表现和固定视口，评审截图差异时优先比较布局、层级和状态，不追求逐像素冻结动态文案。

## 视觉方向

拾语是一个安静的桌面工具，不是一个营销页面。界面以中性灰画布和纯白内容面板构成，主操作是石墨色实心按钮，强调色（靛蓝）只出现在焦点环、链接与选中指示上。不要引入暖米白、大面积品牌色填充、渐变、装饰性发光或大号营销标题。

浅色与深色共用一套规则：颜色全部来自 Radix Themes 的色阶，`<Theme appearance>` 切换时自动翻转。主窗口的画布由 AppShell 绘制，内容卡片、编辑器和弹窗保持不透明；浮动模式没有画布，整页透明。

颜色、间距、圆角与布局变量集中在 [`frontend/src/styles/theme.css`](../frontend/src/styles/theme.css)，全局 reset 与平台窗口层变量在 [`frontend/src/styles/global.css`](../frontend/src/styles/global.css)。组件样式一律是就近的 `.module.css`。

字体跟随宿主系统，不加载网络字体；正文 13px（`scaling="90%"` 下的 size 2），说明 11.5–12px，页面标题 22px。

## 品牌标记与图标

品牌标记是「声纹成字」：左边三根竖条是声纹，右边两条横线是整理后的文字，最高的一根竖条与两条横线共用上下基线。从左往右读就是产品的动作——说话，然后变成文字。

权威几何只有一份：[build/icons/app-icon.svg](../build/icons/app-icon.svg)。应用图标、favicon 与 DMG 文件图标（反相配色）都由它与同目录的变体 SVG 渲染：`common:generate:brand` 出位图，`common:generate:icons` 再把位图转成 `.icns` / `.ico`。**改图标只改 SVG，不要直接改 PNG、ICO、ICNS。**

| 用途 | 源 | 规则 |
| --- | --- | --- |
| 应用图标（macOS / Windows / Linux） | `build/icons/app-icon.svg` | 石墨砖 `#202020`（Radix gray-12 浅色档）+ 白色声纹 + 靛蓝文字线；砖外边距 100、圆角 184，内容 824² |
| DMG 文件图标 | `build/icons/dmg-file.svg` | 反相配色：白砖 + 石墨标记，与应用图标一眼分开（文件不等于应用） |
| DMG 窗口背景 | `build/icons/dmg-background.svg` | 中性灰渐变，不出现任何第三方标识 |
| favicon | 由 `app-icon.svg` 渲染成 64² | 自带砖底，标签页在明暗两套系统外观下都可见 |
| 应用内标记 | [frontend/src/components/BrandMark.tsx](../frontend/src/components/BrandMark.tsx) | 小尺寸精简版：两柱两线、`currentColor` 单色，随主题翻转 |

小尺寸规则：应用内标记用 24 网格，柱宽 = 线高 = 3.4，竖组间距 2.6，14–18px 下仍能读成「左竖右横」。五元素全量版在 32px 以上各自清楚，16px 帧（Windows ico）只保留砖的剪影与声纹节奏；这是刻意取舍，不另做第二套小尺寸艺术稿，两套稿才是不一致的根源。

对比度按 WCAG 对石墨砖 `#202020` 实算：白色 16.3:1、靛蓝 `#5472E4` 3.8:1，都高于非文本图形 3:1 的下限。应用内标记不写死颜色，浅色主题继承 `--app-ink`，深色主题自动变近白。

## 固定视口

| 视图 | 视口 | 期望结果 |
| --- | --- | --- |
| 桌面主视图 | 1280 × 820 | 236px 侧栏、36px 顶带（窗口按钮与品牌同一行）、欢迎区、录音卡和单栏记录卡完整可见；内容列约 720px 居中，两侧留白 |
| 窄桌面 | 1024 × 768 | 录音卡文案与语言标签不重叠，记录卡仍是单栏，底栏按钮不折行 |
| 移动端 | 390 × 844 | 侧栏隐藏、顶栏出现菜单按钮、录音卡与记录卡上下堆叠、记录卡底栏换行、设置表单单列 |
| 主窗口最小 | 640 × 640 | 侧栏收成抽屉、记录卡几乎铺满窗口、底栏不溢出，没有横向滚动 |
| 最小宽度 | 320 × 任意高度 | 标题、按钮和输入框不被裁切，不出现横向滚动 |

主窗口默认 **1000 × 820**（最小 640 × 640）：默认尺寸下内容列几乎铺满，记录卡左右只留 54px；窗口收窄到 956px 以下时内容列跟着窗口一起缩，避免出现大留白。窗口再窄到 680px 会切成侧栏抽屉 + 单列布局。截图仍按 1280 × 820 的评审视口生成，用来观察宽窗口下的留白上限。

响应式规则以 `900px`（窄桌面）和 `680px`（移动端）为边界。Chromium 截图只覆盖内容层；原生交通灯、标题栏和浮动窗口需要在桌面真机上验收。

## 组件状态

| 组件 | 默认 | 交互/工作中 | 空/禁用 |
| --- | --- | --- | --- |
| 录音卡 | 1px 边框、石墨圆形主按钮，波形是一排 14% 高的静默细线 | `data-state="arming"` 按钮外圈呼吸环、波形低频起伏，说明正在申请麦克风；`data-state="recording"` 用红色按钮，波形按真实输入音量缩放；`processing` 按钮禁用并显示旋转图标与耗时。录音中与处理中在说明文字下方多出一枚弱化的「取消这段转写」文字按钮（与浮动球右键菜单等价） | 提示文案说明语言与操作方式；待录音时不出现取消按钮 |
| 记录卡（原始记录一面） | 可编辑文本区，显示字数，右上角是清空与「翻到整理结果」两个图标按钮 | 整理按钮在处理中显示加载图标并禁用；开启流式返回的模型会在这里逐字出字（累计文本覆盖写入，不闪回、不抖动）；转写结束后底栏提示「正在整理，完成后自动翻到结果」 | 无文本时整理按钮禁用 |
| 记录卡（整理结果一面） | 卡内 Markdown 渲染，右上角是复制与「翻回原始记录」 | 有结果时显示重新整理；底栏预设选择器显示当前预设，切换只影响下次整理；整理结果落地时整张卡一次转 180°（约 550ms），转到一半才露出另一面 | 没有结果时用手动翻面可以看到线性图标空状态与禁用的「整理文字」，不把操作藏在悬停里 |
| 预设编辑页 | 左侧预设列表 + 右侧名称与提示词编辑，当前生效项高亮 | 新建、复制、设为当前、删除（AlertDialog 二次确认）；只剩一个时删除禁用 | 名称或提示词为空时就地提示，不隐藏保存按钮 |
| 侧栏导航 | 中性文字，`aria-current="page"` 表示选中 | 悬停浅灰底；数量为 0 时不渲染数字 | — |
| 设置弹窗 | Radix Dialog + 三个 Tab | 焦点陷阱、Esc 关闭、遮罩点击关闭 | 取消是低强调按钮 |
| Toast | 底部居中，1px 边框带阴影 | 成功 2.6 秒、失败 5 秒后自动消失 | — |
| 调用概要条 | 一行 chip：接口类型、模型、音频时长、耗时、实时倍率、token | 点「详情」展开字段网格与原始 usage（Collapsible） | 没有调用时显示「等待调用」 |
| 调用记录页 | 每次调用一行，成功绿色勾选、失败红色警示 | 展开行显示与概要条相同的详情；顶部汇总成功/失败/总耗时/总 token | 无调用时显示空状态 |
| 应用顶带 | 36px 一行：macOS 原生交通灯与品牌、面包屑、窗口操作同处一条水平线；Windows/Linux 在顶带之上另有 32px caption | 拖动顶带移动窗口；Windows/Linux 双击 caption 最大化；⌘\ 折叠侧栏 | 浮动模式没有顶带 |
| 侧栏折叠 | 顶带右侧是收起按钮，侧栏占据布局左侧 | 内容先淡出 90ms，侧栏再滑出 200ms；顶栏接管窗口左上角，显示「展开侧栏」「新建记录」 | 侧栏内容 `inert`，Tab 不会进入；抽屉形态（≤680px）同一按钮改为关闭菜单 |

状态必须同时有文案或图标，不得只通过颜色区分。系统开启 `prefers-reduced-motion` 时，波形、Toast 和按钮过渡应快速结束，记录卡翻面改为淡入淡出，都不改变内容状态。

## 桌面专属状态

桌面窗口有两个视觉模式：主窗口保持编辑器布局，左侧导航固定、右侧内容独立滚动，顶部使用原生交通灯（macOS）或平台 caption（Windows/Linux）；浮动模式是 92×92 的透明窗口，只显示圆形录音按钮，不出现方形底色、标题栏或交通灯。浮动按钮待录音时是石墨色麦克风，正在开启麦克风时保持麦克风图标并加呼吸环（球体不缩放），录音中才是红色方块并随输入音量放大、带一圈音晕，整理中为旋转图标；缩放后的球加外圈仍在 92×92 窗口内。交互手势与状态机见 [`docs/desktop-interaction.md`](desktop-interaction.md)。自动粘贴失败时，结果仍保留在剪贴板，不能阻塞历史记录和复制操作。

## 人工验收清单

1. 桌面视图没有横向滚动，侧栏与主内容之间只有一条细分隔线。
2. 开始录音、录音中、结束录音和处理中四个阶段都能通过文案及图标辨认。
3. 记录卡两面的标题、辅助说明和内容层级清楚；翻面只换内容，不改变卡片的位置与高度基准；空结果不把操作藏在悬停状态。
4. Tab 键能依次到达导航、录音、记录卡当前一面上的操作和设置控件；背面控件不在 Tab 序列里，翻面后焦点落在新一面的标题上。
5. 390px 宽度下没有被截断的标题、按钮或表单字段，设置弹窗的表单变为单列；打开菜单后侧栏可点遮罩关闭。
6. 开启「减少动态效果」后，波形与 Toast 不持续闪动；记录卡翻面不旋转、只淡入淡出，颜色仍符合状态契约。
7. 调用概要条与调用记录页在 1280px 和 390px 下都不横向溢出；展开后的详情网格按可用宽度自动换列。
8. 浅色与深色两套下，文字与背景的对比度都足够，没有任何色块在切换后糊成一片。
9. macOS 主窗口左上角是原生交通灯，与品牌、面包屑处于同一水平线；36px 顶带的内容中心落在 18px，和 16px 处的灯心基本齐平，没有额外空白行，正文对比度正常。
10. Windows 11 标题栏按钮 hover/最大化还原正确，自绘 caption 与画布之间没有透明缝隙；系统关闭透明效果时不依赖任何原生材质。
11. 浮动模式没有标题栏、交通灯或方形底色；右键弹出的是系统原生菜单；展开后交通灯和完整画布恢复。
12. 设置里切换整理预设后，记录卡两面的底栏选择器同步；重新整理时调用概要条出现该预设的名称，390px 下预设选择器与「重新整理」按钮换行而不溢出。
13. 点击浮动球后先出现呼吸环的「开启麦克风」状态，麦克风就绪才变成红色停止图标；安静时球保持基准大小，说话时随音量放大，音晕随音量加深，全程不超出 92×92 窗口。
14. 折叠侧栏时「拾语」先淡出再滑走，不会从交通灯下方横穿；展开时侧栏先就位、内容随后淡入；收起后顶栏左侧立即出现「展开侧栏」「新建记录」，窗口不在前台时也照样可见（不依赖入场动画）。
15. 录音中与处理中都能看到「取消这段转写」：主窗口是说明文字下方的文字按钮，浮动球是右键菜单项（待录音时置灰）。取消后界面立刻回到待录音、没有历史记录、也不弹错误提示。
16. 侧栏与 Windows/Linux 标题栏的品牌标记是「两柱两线」的新标记，16px 下不糊成一团，浅色与深色主题都跟文字同色；macOS 程序坞与 Windows 任务栏里的应用图标是石墨砖配声纹，不是旧的「W」。

## 生成截图

不引入额外浏览器依赖；已安装 Chromium 或 Google Chrome 的环境可直接运行：

```bash
cd frontend
./scripts/capture-visual-baseline.sh
```

脚本先执行 Vite 构建，再把 `docs/visual-baseline/` 作为唯一输出目录，生成 `idle-1280.png` 和 `idle-390.png`。可通过 `CHROMIUM_BIN=/path/to/chromium` 指定浏览器，或把输出目录作为第一个参数传入。脚本会为 headless 浏览器使用临时用户目录；Edge 等 Chromium 分支会把小窗口钳制到约 492px，生成 390px 截图时请使用 Chromium/Chrome。

没有 Chromium 时，可以用 ego-browser 以 1280×820 与 390×844 两个视口直接截图，深浅两套分别是 `idle-1280.png`、`idle-390.png` 与 `idle-1280-dark.png`、`idle-390-dark.png`。浏览器预览还可以用 `?platform=windows` 强制渲染 Windows 标题栏，方便在 macOS 上检查 caption 布局。截图用于人工差异评审，动态日期和问候语不作为像素测试条件；原生窗口层需要在桌面真机上另做验收。
